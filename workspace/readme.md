# workspace/

Your personal working area. Everything here is gitignored except this readme,
so you can keep scripts, research and scratch data in the repo without ever
committing them by accident.

```
workspace/
  indicators/   generated by the indicator skills
    charts/       chart scripts        (/indicator-chart)
    scanners/     scanner scripts      (/indicator-scanner)
    custom/       indicator modules    (/custom-indicator)
    dashboards/   Dash / Streamlit     (/indicator-dashboard)
    feeds/        live WebSocket       (/live-feed)
    data/         cached OHLCV
    output/       rendered .html / .png / .csv
  research/     ad-hoc analysis, notebooks, one-off scripts
  backtests/    backtest runs and their results
  notes/        working notes
```

Add your own subfolders freely — the ignore rule covers the whole tree.

## What does NOT go here

**`workspace/strategies/` does not exist, deliberately.** The `/python`
Strategy Host reads from the top-level **`strategies/`** directory, which the
application manages itself: it enforces a path-traversal boundary on uploads,
sets its own permissions, and has a tuned `.gitignore` that keeps the examples
while ignoring your scripts and config. A strategy placed under `workspace/`
would simply never run. Put strategies in `strategies/`.

Likewise `db/`, `log/`, `keys/` and `tmp/` are app-managed and already handled.

## Secrets

**Do not keep credentials here.** Gitignore prevents accidental commits; it is
not a secrecy boundary:

- `git add -f` bypasses it entirely
- it does not stop a backup, an archive, or someone zipping the repo
- the Docker build runs `COPY . .`, so exclusion depends on `.dockerignore` (`workspace/` is listed there — keep it that way)

API keys and broker credentials belong in `.env`, which is already gitignored,
already excluded from Docker images, and expected to be `chmod 600`. Encryption
material belongs in `keys/`.

## What is tracked

```
workspace/**
!workspace/**/
!workspace/readme.md
!workspace/**/readme.md
```

Every folder ships a `readme.md` explaining what belongs in it — that is what
makes the directory exist after a clone, since git does not track empty
directories. Everything else you put here stays local.

The skills still `mkdir -p` before writing, so a folder you delete is recreated
on demand.

## Running

From the repo root, using OpenAlgo's own environment:

```bash
uv run --group analysis python workspace/indicators/charts/ema_SBIN_D.py
uv run --group analysis streamlit run workspace/indicators/dashboards/app.py
```

Scripts needing only `openalgo`, `pandas`, `numpy` or `plotly` can drop
`--group analysis` — those are main dependencies. See
`.claude/skills/indicator-setup/` for setup.

## Naming

`<indicator>_<symbol>_<interval>.py`, with rendered artifacts under `output/`
sharing the stem:

```
workspace/indicators/charts/ema_SBIN_D.py  ->  workspace/indicators/output/ema_SBIN_D.html
```
