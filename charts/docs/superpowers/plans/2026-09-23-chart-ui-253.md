# Chart interface 2.5.3 implementation plan

> **For agentic workers:** Use the parallel-agent workflow for the exclusive file groups below, followed by integration and independent review. Shared integration files have one writer.

**Goal:** Ship the six approved interface improvements in 2.5.3 without changing trading ownership or adopting a packaged workspace.

**Architecture:** Reusable DOM components live in the widget tier and consume public engine APIs. Object operations live in the model and drawing tiers. The widget and yfinance host compose the same components.

**Tech stack:** Existing TypeScript, native DOM/CSS, Vitest, Playwright and the current website stack. No new runtime packages.

**Spec:** `docs/superpowers/specs/2026-09-23-chart-ui-253-design.md`

## Global constraints

- Nine tiers; only widget contains DOM; zero new runtime dependencies.
- Additive interfaces and backwards-compatible persistence.
- Preserve existing keyboard precedence, alerts, replay, formatting and instrument identity.
- Do not edit active OpenAlgo. Keep comparisons outside this repository.
- Plain English, existing design tokens and compact rows; no new branding.
- Base revision: `253ae714d4a5a49f8d4b71a4fd1dca33e18d3d0b`.

## Review focus

- Old or malformed stored state must restore safely without dangling groups or invalid panel widths.
- Rapid typing and asynchronous result races cannot select the wrong symbol or exchange.
- Indicator movement preserves identity, plot ownership, attached alerts and saved pane indices.
- Missing/OI-zero/readout gaps remain distinct through replay, live updates and context switches.
- Focus, popovers, editable text and drawing gestures cannot compete for keyboard or pointer ownership.
